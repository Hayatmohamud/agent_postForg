# PostForge — Project Contract & Conventions

PostForge is a greenfield **autonomous multi-agent content generator**: a user submits a topic → an
AgentKit network (**Research → Verify → Write → Edit → Illustrate → Publish**) runs inside an **Inngest**
durable function → the finished post + poster persist to **MongoDB**, and the UI shows live progress by
polling. Full architecture: `PLAN.md`. Design brief: `DESIGN_PROMPT.md`.

## ⚠️ Next.js — breaking changes vs your training data
**Versions installed by T01 (record for downstream tasks):** Next.js `16.3.5`, React `19.2.8`, Tailwind CSS `^4` (via `@tailwindcss/postcss`), ESLint `^9` with `eslint-config-next@16.3.5` (flat config — `eslint.config.mjs`, not `.eslintrc`), TypeScript `^5`, Node `24.19.0` (built/verified against; `@types/node` pinned to `^22` because `vitest@5` requires `@types/node` `^22 || >=24`), Inngest `4.20.0`, `@inngest/agent-kit` `0.13.2`, `mongodb` `7.6.0`, `zod` `4.6.5`, `@google/genai` `2.22.0`, `openai` `7.15.0`, `vitest` `5.0.1`.

Recent Next.js majors change APIs/conventions frequently (async request APIs — dynamic route `params`/`searchParams` are `Promise`s and must be `await`ed even in Route Handlers; `next lint` removed in favor of flat-config `eslint`; Turbopack is the `next dev` default in v16, but `npm run build` in this repo explicitly passes `--webpack` — see the worktree pitfall below). **Before writing any Next.js / React / Tailwind code, read the relevant guide in `node_modules/next/dist/docs/`** and confirm against live docs (Context7 MCP or web search) — never rely on training-data memory. The imported `AGENTS.md` carries the same advisory.

**Worktree build note:** `post-forge/package.json`'s `build` script runs `next build --webpack`, not the Turbopack default, because Turbopack builds can fail inside a git worktree when `node_modules` resolves outside the worktree root (see `tasks/README.md`'s known pitfalls). `next dev` still uses Turbopack (unaffected in testing here). Re-verify a plain Turbopack `next build` after merging to `main`, where `node_modules` is no longer worktree-relative.

**Inngest local dev note:** Inngest v4 defaults to cloud mode, so `post-forge/package.json`'s `dev` script sets `INNGEST_DEV=1` (via `cross-env` for Windows/POSIX portability) — without it `/api/inngest` 500s when `npx inngest-cli@latest dev` tries to sync locally. Verified in T01: with `INNGEST_DEV=1` set, `GET /api/inngest` reports `{"mode":"dev","function_count":0,...}` and the Inngest dev server (`inngest-cli@1.44.0`) syncs the `post-forge` app with zero functions registered, as expected until T05.

## How this project is built (orchestration)
- The build is driven by the **Orchestrator** model in `ORCHESTRATOR.md`. Tasks **T01–T19** each have a BRD in `tasks/`.
- **`tasks/status.json` is the single source of truth** for task state — read it at the top of every cycle; never act from memory. Keep it and the status table in `tasks/README.md` in sync on **every** state change.
- Tasks run in **waves**; a task is `ready` only when every id in its `dependsOn` is `done`. Same-wave tasks run in isolated **git worktrees** branched off `main`, merged back after verification.
- Implementers never guess on a blocker / decision / broken-assumption / missing-dependency — they file a report in `tasks/reports.jsonl` (protocol: `tasks/REPORTS.md`); the orchestrator triages and escalates human decisions.
- **Verification is mandatory before `done`:** `command` tasks run build / typecheck / test / DB checks; `screen` (UI) tasks are screenshotted at **desktop + mobile** via Claude-in-Chrome and compared against the design system (T07) + the task's acceptance criteria.
- `tasks/README.md`'s "Known pitfalls from a prior build" section documents real bugs a previous implementation of this exact plan hit and fixed — read it before dispatching T02–T19 and bake the relevant ones into each brief.

## Locked decisions (apply everywhere)
- **Auth:** ~~cosmetic stub~~ **superseded post-T16, per explicit user request:** real login via Auth.js (NextAuth v5), `src/auth.ts` — Google OAuth, GitHub OAuth, **and** email+password with mandatory email verification. JWT session strategy throughout (Auth.js's default with no `adapter` configured, and the only strategy the `Credentials` provider supports) — deliberately **not** using `@auth/mongodb-adapter`, whose latest release requires `mongodb@^6` while this project is pinned to `mongodb@^7` (see the version table above). OAuth sessions need no database record at all; email+password accounts need *some* persistent record to check a password against, so they live in a plain `users` collection (`src/lib/users-repo.ts`) written directly with the existing `mongodb` driver — no adapter package involved. The app is still single-tenant / no `userId` on posts — login gates *access* to the app shell (`src/proxy.ts` protects `/dashboard`, `/new-post`, `/library`, `/scheduled`, `/settings`, `/posts/*`, redirecting to `/sign-in`), it does not scope data per-user.
  - **Email+password verification flow:** `POST /api/auth/signup` creates an unverified user + emails a 6-digit OTP (Resend, `src/lib/email.ts`); `POST /api/auth/verify-otp` checks it (`src/lib/otp-repo.ts` — bcrypt-hashed code, 10-minute TTL via a Mongo TTL index, 60s resend cooldown, 5 wrong-attempt cap) and marks the user verified; the client then calls `signIn("credentials", ...)` itself — an account can never sign in before its email is verified (`src/auth.ts`'s `authorize()` throws `EmailNotVerifiedError` otherwise, code `email-not-verified`, which the sign-in page detects to drop the user into the same OTP-entry step and retry login on success). `OtpForm` (`src/components/auth/OtpForm.tsx`) is shared between the sign-up and sign-in-recovery flows.
  - Requires real `AUTH_GOOGLE_ID`/`AUTH_GOOGLE_SECRET`, `AUTH_GITHUB_ID`/`AUTH_GITHUB_SECRET`, and `RESEND_API_KEY` (see Env contract below), registered/obtained by the user themselves; without the OAuth ones those buttons hit Auth.js's own configuration-error page, and without `RESEND_API_KEY` sign-up's OTP email send fails with a 502 (`email_send_failed`).
- **API keys:** env-only. Settings shows integration status + test-connection; **never** key entry.
- **Live progress:** poll `GET /api/posts/[id]` + persisted per-stage sub-progress (reveal-on-update; no token streaming).
- **Doc ownership:** `POST /api/generate` creates the post doc + mints `runId`; the Inngest function only *updates* it.
- **Design system:** originally implemented **directly in code** in T07 (Tailwind tokens + `src/components/ui`) from `DESIGN_PROMPT.md`. **Superseded post-T16** by a mockup import from a `claude.ai/design` project (`PostForge.dc.html`, via the DesignSync MCP) — the T07 tokens' two decisions below are no longer accurate; everything else about T07 (token *names*, `src/components/ui`'s structure) still holds, only *values* changed:
  - **Brand accent is green** (was indigo) — `--color-brand-*` in `src/app/globals.css` now derives from an oklch green ramp; six agent-stage accents were retinted to match.
  - **Dark mode is real**, not light-only — `[data-theme="dark"]` overrides the same `@theme` custom properties in `globals.css`; theme state/persistence lives in `src/lib/theme.ts` + `src/hooks/useTheme.ts`, toggled from the Topbar and Settings > Appearance. `src/components/charts/theme.ts` mirrors both palettes in hex (documented reason: unreliable `var()` resolution in Recharts SVG) via a `useChartColors()` hook — update both light and dark objects there if a color token changes.
  - Fonts are now **Instrument Sans / Newsreader / JetBrains Mono** (was Geist / Lora / Geist Mono), wired in `src/lib/fonts.ts`.
  - Still true: tokens are managed centrally (now in `globals.css` + the two files above); no other task should redefine them ad hoc.

## Env contract (`.env`, mirrored by `.env.example`)
**Amended in T02 (per the reference build's proven working setup): all text AI routes through OpenRouter.** One key covers every text model call. Read through `src/lib/env.ts` (`requireEnv` throws a named error when a required var is missing):
- `OPENROUTER_API_KEY` (accessor also accepts legacy alias `OPEN_ROUTER`) — the single key for every text model call.
- `SERPER_API_KEY` — web search.
- `MONGODB_URI` — persistence + GridFS poster bytes (local dev: `mongodb://127.0.0.1:27017/postforge`).
- **Model tiers** (OpenRouter ids, env-overridable): `LLM_MODEL_SMART` (default `openai/gpt-5.5`), `LLM_MODEL_CHEAP` (default `google/gemini-2.5-flash-lite`), `LLM_MODEL` (general fallback).
- `INNGEST_EVENT_KEY` / `INNGEST_SIGNING_KEY` — only required for non-local Inngest.
- T01's `.env.example` predates this amendment (separate `GEMINI_API_KEY`/`OPENAI_API_KEY`/`IMAGE_PROVIDER`) — **T02 updates `.env.example` and `src/lib/env.ts` to match this contract.**
- If a subagent discovers a further reason to change this contract, that's an `assumption-broken`/`suggestion` report, not a silent change — the orchestrator decides.

**Further amendment (post-T16): text AI moved from OpenRouter to Gemini**, per an explicit user decision. `OPENROUTER_API_KEY`/`OPEN_ROUTER` are gone from the contract entirely (removed from `EnvVarName`, not just deprecated).
- `GEMINI_API_KEY` — text generation (research/verify/write/edit). Get one at aistudio.google.com/apikey.
- **Text** (`src/lib/models.ts`): still built on AgentKit's `openai()` adapter (unchanged integration shape) but pointed at Gemini's OpenAI-compatible endpoint (`https://generativelanguage.googleapis.com/v1beta/openai/`, verified live 2026-09) instead of OpenRouter's. `LLM_MODEL_SMART`/`LLM_MODEL_CHEAP` now hold **Gemini** model ids (defaults `gemini-3.5-flash` / `gemini-3.1-flash-lite`), not OpenRouter ids. The `LLM_MODEL` general-fallback var and its sole consumer (`models.ts`'s `gpt5()`) were unused dead code and were deleted rather than migrated.
- **Known account limitation, verified live (2026-09):** this project's `GEMINI_API_KEY` has **zero free-tier quota for any "pro"-tier model** (`gemini-3.1-pro`/`gemini-pro-latest`/`gemini-2.5-pro` all 404 or 429 with `limit: 0`) — that's why `LLM_MODEL_SMART` defaults to a flash-tier model instead of a pro one. If the account's plan changes, re-verify quota with a real `chat/completions` call before switching the default back to a pro model — a 404/429 on that call fails every generation run.
- **Poster images stayed on / moved back to Replicate** (`REPLICATE_API_KEY`, `src/lib/image.ts`, `IMAGE_MODEL` holds a Replicate `owner/name` id, default `black-forest-labs/flux-schnell`) — **not** Gemini's own image models. Reason, verified live the same day: this account's `GEMINI_API_KEY` has zero free-tier quota for *every* Gemini image model tested (`gemini-2.5-flash-image`, `gemini-3.1-flash-image`, `gemini-3.1-flash-lite-image`, `gemini-3-pro-image`, `nano-banana-pro-preview` — all 429 `limit: 0`), a Google Cloud billing restriction, not a code bug. The user already held a working Replicate key, so illustration was pointed back at it while text stayed on Gemini. `/api/settings/test` accordingly has two separate probes again: `gemini` (text) and `image` (Replicate).
- **Required fix — Gemini 3's mandatory "thought signature" round-trip (found + fixed 2026-09):** every tool-using text agent (research, verify) hung indefinitely on its second turn when this migration first landed. Root cause: Gemini 3 models attach an encrypted `choices[].message.tool_calls[].extra_content.google.thought_signature` to every tool-call response, and **require that exact value echoed back** on the next request's reconstructed assistant `tool_calls` message — AgentKit's `openai()` adapter (built for the standard OpenAI schema) has no field for this vendor extension and silently drops it, so Gemini rejects the follow-up with `400 INVALID_ARGUMENT: Function call is missing a thought_signature`. Not fixable via a request parameter (`reasoning_effort: "none"` was tested live; Gemini still requires the signature). Fixed in `src/lib/models.ts` by patching `globalThis.fetch` to capture each tool call's signature (keyed by its model-generated `id`) and replay it on the matching follow-up request, transparently to AgentKit. See that file's doc comment for the full write-up and how it was diagnosed (raw HTTP interception + a bare-`curl` reproduction). **Any future AgentKit/Gemini upgrade should re-verify this is still needed** — if a newer `@inngest/agent-kit` release adds native Gemini thought-signature support, this patch becomes redundant (harmless either way, since it only fills in a field that would otherwise be missing) and can be removed.
- **Graceful degradation for a permanently-failing stage:** a stage whose *tool itself* fails (not just a weak model skipping the call — e.g. the image provider being down/out of quota) used to leave the pipeline stuck retrying forever, bounded only by the network's `maxIter` safety cap (a slow, opaque "failed" after 24 router iterations). The illustrator agent (`src/agents/illustrator.ts`) now sets `state.posterSkipped = true` when its fallback `generate_poster` call itself throws, and `routeNext`/`isStageComplete` (`src/agents/network.ts`, `src/inngest/functions.ts`) treat that the same as stage-complete — the post still finishes and publishes, just without a poster, per explicit product decision. This pattern (a `*Skipped` state flag) is the template for making any other stage degrade the same way if it ever needs to. Verified live end-to-end: a real run completed research→verify→write→edit→(illustrate skipped)→publish→done with a genuine Gemini-written article and no poster.
- The `/api/settings/test` provider enum is `gemini` | `image` | `serper` | `mongodb` — `gemini` probes `GET /v1beta/models`, `image` probes Replicate's `GET /v1/account` (see `src/app/api/settings/test/route.ts`).

**Auth (post-T16, real OAuth):**
- `AUTH_SECRET` — signs/encrypts the JWT session cookie. Generate with `openssl rand -base64 32` (or Node's `crypto.randomBytes(32).toString("base64")`); required for Auth.js to boot.
- `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` — from a Google Cloud Console OAuth client (type "Web application"), authorized redirect URI `http://localhost:3000/api/auth/callback/google` in dev.
- `AUTH_GITHUB_ID` / `AUTH_GITHUB_SECRET` — from a GitHub OAuth App (github.com/settings/developers), authorization callback URL `http://localhost:3000/api/auth/callback/github` in dev.
- These four are read directly by Auth.js via its own env var convention (`src/auth.ts`), not through `src/lib/env.ts`'s `EnvVarName` union — Auth.js infers `clientId`/`clientSecret` from `AUTH_<PROVIDER>_ID`/`AUTH_<PROVIDER>_SECRET` automatically when a provider is listed with no explicit config.
- `RESEND_API_KEY` — sends the sign-up OTP email (`src/lib/email.ts`, `requireResendKey()` in `src/lib/env.ts`). Get one at resend.com/api-keys.
- `RESEND_FROM_EMAIL` — optional, defaults to Resend's sandbox sender `onboarding@resend.dev` (works with no domain verification, but only delivers to the Resend account's own address — verify a domain to send to arbitrary addresses).
